# 并发压缩设计与验证

用户要求将压缩由串行改为并发，提高批量效率。

## 实现约定

- 同时处理 2 张图片，保留列表原顺序，完成顺序可不同。
- WebP 编码放入 2 个独立 Worker，各自独占 WASM 实例，避免主线程阻塞与共享编码器状态。
- 图片在主线程解码和绘制，RGBA 缓冲区通过 Transferable 移交 Worker，避免复制大像素数组。JPG/PNG 继续使用系统 Canvas 异步编码。
- 每批次独立 Worker 池，批次完成后释放。停止时立即终止 Worker、停止领取新任务，未完成图片恢复待处理；已完成结果保留。
- 一张失败不阻断其他任务；重试仅处理未完成图片。
- 发行构建 CSP 允许同源 Worker，实际打包路径需通过原生 WebView 检查。

## 验证步骤

1. 固定种子的 8 张 1600×1000 图片，串行基线与 Worker 并发各重复三次，记录中位数和主线程延迟。
2. 重跑既有原生编码测试，验证格式、尺寸、透明度及无损像素。
3. 验证队列并发上限、两张同时处于处理中、乱序完成不串图、失败隔离、停止和重新开始。
4. TypeScript 检查、Go 测试、发行包构建；实际 mygo:// 页面验证 Worker 加载。

## 实测结果

同一台 Mac、同一 WKWebView、固定种子图片、编码器预热后，每组处理 8 张 1600×1000 静态 PNG → WebP（80% 质量），每种方式 3 次：

| 方式 | 3 次批量耗时（ms） | 中位数 | 主线程最大延迟 |
| --- | --- | --- | --- |
| 原主线程串行 | 1172 / 1173 / 1170 | 1172 ms | 137 ms |
| Worker 单并发 | 1180 / 1183 / 1174 | 1180 ms | 13 ms |
| Worker 双并发 | 669 / 692 / 629 | 669 ms | 20 ms |

该样本耗时缩短约 43%，吞吐量约为原来的 1.75 倍。此为固定样本、预热后的结果，不代表所有图片或设备的固定提升；低分辨率小图的线程启动成本占比会更高。

数据：`test-results/benchmark-before.json`、`test-results/benchmark-after.json`。

验证：4 项并发调度测试与原有 18 项原生编码检查通过。打包版 `mygo://localhost/` 下 Worker 加载和编码成功。
